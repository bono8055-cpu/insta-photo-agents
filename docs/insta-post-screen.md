# 인스타 게시 — 화면 명세

작성 2026-10-10. `insta-post-spec.md` 8절을 풀어 쓴 문서다. 엔진(4~6절)과 같이 읽는다.

## 0. 실행 방식 (PC 1단계)

- `python server.py` → 브라우저가 `http://127.0.0.1:8765`를 연다.
- 구성: 파이썬 표준 라이브러리 `http.server` + `web/index.html` 한 장(HTML·JS, 외부 라이브러리 없음).
- 근거: 엔진과 같은 파이썬만으로 돌아 설치할 게 없다. 이 화면은 나중에 폰 앱 화면으로 바뀌는 임시 화면이라 프레임워크를 들이지 않는다.
- `127.0.0.1`에만 연다. 서버가 토큰을 들고 있어서 같은 네트워크의 다른 기기가 열면 안 된다.
- 파이썬 3.13부터 `cgi` 모듈이 없다. multipart를 쓰지 않고 사진을 한 장씩 요청 본문(raw)으로 보낸다.

## 1. 화면 구성 (한 페이지, 위에서 아래로)

```
+--------------------------------------------------------------+
| 인스타 게시          [O] @계정   [O] 호스팅 쓰기 가능  [다시 확인] |
+--------------------------------------------------------------+
| [사진 고르기]  또는 여기에 끌어다 놓기 (최대 10장)                 |
|  +------+  +------+  +------+                                 |
|  |  1   |  |  2   |  |  3   |                                 |
|  | 첫장 |  |      |  |      |                                 |
|  +------+  +------+  +------+                                 |
|  <  >  x   <  >  x   <  >  x                                  |
|  1440x1800 1.2MB ...                                          |
| 비율: (자동) (4:5) (1:1) (1.91:1)    자동 -> 4:5, 세로 6% 잘림    |
+--------------------------------------------------------------+
| 캡션                                                          |
| [                                                          ]  |
| 123 / 2200자   해시태그 5 / 30                                 |
+--------------------------------------------------------------+
|                                            [인스타에 게시]      |
+--------------------------------------------------------------+
```

## 2. 영역별 동작

### 연결 상태
- 페이지를 열 때와 [다시 확인]을 누를 때 엔진 `check`를 부른다.
- 정상: `@계정`, `호스팅 쓰기 가능`을 초록으로 표시.
- 실패: 빨간 표시 + 원인 한 줄(4절 문구). 실패 중에는 게시 버튼을 막는다.

### 사진
- [사진 고르기] 또는 끌어다 놓기. jpg·png·webp만. 10장을 넘으면 앞 10장만 받고 안내한다.
- 순서는 고른 순서. 썸네일 아래 `<` `>`로 옮기고 `x`로 뺀다. 1번 칸에 "첫 장"을 표시한다(캐러셀 비율 기준).
- 사진·순서·비율이 바뀔 때마다 `prepare`를 다시 부른다(마지막 변경 후 0.3초 뒤 한 번). 처리 중인 썸네일에는 "맞추는 중"을 띄운다.
- 썸네일은 원본이 아니라 `prepare` 결과(잘린 사진)를 보여 준다. 아래에 결과 크기와 용량을 적는다.

### 비율
- 칩 4개: 자동(기본) / 4:5 / 1:1 / 1.91:1.
- 자동이면 실제로 적용된 비율을 옆에 적는다(예: "자동 -> 4:5"). 잘린 양도 적는다(예: "세로 6% 잘림").

### 캡션
- 여러 줄 입력. 글자 수 `n / 2200`, 해시태그 수 `n / 30`을 아래에 표시한다(한도 값은 명세 3절의 확인 결과를 따른다).
- 한도를 넘으면 숫자를 빨갛게 하고 게시 버튼을 막는다.

### 게시
- 버튼이 켜지는 조건: 연결 정상 + 사진 1장 이상 + `prepare` 완료 + 캡션 한도 이내.
- 누르면 확인창: "사진 N장을 @계정에 실제로 게시한다. 되돌릴 수 없다." [게시] [취소].
- 진행 중: 버튼을 막고 "게시 중 (최대 2분)"을 띄운다. 끝나면 엔진의 단계 기록(`log`)을 펼쳐 볼 수 있게 둔다.
- 성공: 게시물 링크(permalink) + [새 게시] 버튼(사진·캡션 비움). 같은 작업은 버튼을 "게시 완료"로 바꿔 다시 못 누르게 한다. 경고(호스팅 삭제 실패 등)는 노란 줄로.
- 실패: 빨간 줄에 원인과 멈춘 단계. 사진·캡션은 그대로 둬서 바로 다시 시도할 수 있게 한다.

## 3. 화면 ↔ 서버 (`server.py`)

| 메서드 | 경로 | 보내는 것 | 받는 것 |
|---|---|---|---|
| GET | `/api/check` | — | 엔진 `check` 결과 |
| POST | `/api/job` | — | `{job}` 새 작업 id |
| POST | `/api/photo?job=&name=` | 사진 한 장(본문 그대로) | `{i, w, h}` |
| POST | `/api/prepare` | `{job, order: [i...], ratio}` | `{ratio, items: [{k, w, h, bytes, cropPct}]}` |
| GET | `/api/image?job=&k=&v=` | — | 준비된 사진(미리보기, `v`는 캐시 무효용) |
| POST | `/api/publish` | `{job, caption}` | `{mediaId, permalink, log, warnings}` 또는 `{error, step, log}` |

- 작업 폴더: `work/<job>/` (원본 `src_NN.*`, 결과 `post_KK.jpg`, 게시 완료 표시 `published.json`). `work/`는 `.gitignore`에 넣는다.
- `job`은 서버가 만든 16자리 16진수만 받는다(경로 조작 방지).
- 24시간 지난 작업 폴더는 서버를 켤 때와 새 작업을 만들 때 지운다.
- 엔진 호출은 한 번에 하나씩. `publish`는 시간 제한 300초, 나머지는 60초.

## 4. 오류 문구

| 상황 | 화면 문구 |
|---|---|
| 인스타 토큰 없음·만료 | 인스타 토큰이 없거나 만료됐다. `.env`의 `INSTAGRAM_ACCESS_TOKEN`을 새로 넣는다 |
| 호스팅 토큰 권한 부족 | 호스팅 토큰에 저장소 쓰기 권한이 없다 |
| 호스팅 저장소가 비공개 | 저장소가 비공개라 인스타가 사진을 가져갈 수 없다 |
| raw 주소가 30초 안에 안 열림 | GitHub에서 사진 주소가 열리지 않았다. 잠시 뒤 다시 시도한다 |
| 게시 한도 초과 | 24시간 게시 한도를 넘었다 |
| 그 밖의 인스타 오류 | 인스타가 보낸 메시지를 그대로 보여 준다(토큰이 들어간 주소는 지운다) |

## 5. 폰 앱 화면 흐름 (이후 단계 — 참고)

1. 갤러리에서 사진 여러 장 선택(안드로이드는 갤러리 "공유 -> 이 앱"도 가능).
2. 보정: 키스톤 자동 → 색감(기준 사진 1장 지정, 흰 표면 기준 자동) → 보정 전후 비교. 사진별로 보정을 끌 수 있다.
3. 게시할 사진 고르기와 순서 정하기.
4. 비율·캡션·게시: 이 문서 2절과 같은 규칙.
5. 설정 화면: 인스타 토큰·호스팅 토큰 입력(폰 암호화 저장소), 토큰 만료일 표시.

## 6. 검증

- 명세 9절의 모의 서버를 켜고 `server.py`를 모의 주소로 띄운 뒤 브라우저에서 확인한다.
  - 1장 게시, 3장 캐러셀 게시가 링크까지 나오는지.
  - 순서를 바꾸면 첫 장 기준 비율이 다시 계산되는지.
  - 토큰을 비우면 연결 상태가 빨갛게 되고 게시 버튼이 막히는지.
  - 게시 중 버튼을 두 번 눌러도 한 번만 게시되는지.
- 실계정은 모의 시험 통과 후 1장 → 캐러셀 순서로 한 번씩.
